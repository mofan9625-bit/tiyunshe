Clash 与 Clash Verge 测试超时、连接后无法访问：完整排错教程

从订阅、系统代理、DNS、规则与内核日志逐层排查 Clash 连接问题。

TY

梯云社编辑部

Network Research · 2026

遇到“测试超时”时，最常见的错误是反复更换节点，却没有先确认订阅是否更新、系统代理是否生效、DNS 是否可用。节点延迟测试、TCP 连通和网页访问是三条不同链路；其中任何一环失败，都可能显示为“连上但无法访问”。

先判断故障在哪一层

现象延迟峰值速率晚高峰表现解锁支持优先检查
所有节点超时无结果0全天失败无订阅、内核、防火墙
仅部分节点超时高或无结果不稳定可能恶化部分可用节点状态、地区线路
显示延迟但网页打不开正常0无关无系统代理、DNS、规则
网页可用但目标服务失败正常正常可能正常不支持规则命中、出口 IP

第一步：检查配置与内核

确认订阅更新时间不是很久以前，配置文件能被客户端正常解析。查看日志是否出现 parse error、bind failed 或端口占用。若本地端口冲突，关闭重复运行的同类客户端，再重启 Clash Verge。

第二步：确认系统代理

开启系统代理后，浏览器应指向客户端监听端口。若浏览器安装了独立代理扩展，可能覆盖系统设置。临时禁用扩展，用一个全新隐私窗口测试，避免缓存与旧规则干扰。

第三步：处理 DNS

网页提示找不到域名，而 IP 测试正常，通常是 DNS 问题。检查配置中的 DNS 服务器是否可达，fake-ip 模式是否与本地软件兼容。修改前备份配置，一次只改变一个变量，避免无法回溯。

第四步：查看规则命中

在连接列表中找到目标域名，确认它命中了预期策略组。如果落入 DIRECT 或错误地区，调整规则顺序。规则从上到下匹配，过于宽泛的规则放在前面会遮蔽后续条目。

仍无法定位？领取可测试节点并对照标准配置，先排除订阅与节点本身的故障。

最小化恢复方案

新建一份最小配置，只保留一个已验证节点、基础 DNS 和全局模式。若最小配置可用，再逐项恢复规则、脚本与扩展。这样比直接重装更容易找到真正原因，也能保留原有数据。
