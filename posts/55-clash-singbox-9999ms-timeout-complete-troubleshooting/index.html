【拒绝CSDN套话】Clash Verge Rev / sing-box 节点全部 9999ms 超时：全链路七步排查树

拒绝 CSDN 复制粘贴与无脑重装！梯云社工程师整理的 Clash Verge Rev 与 sing-box 节点全部 9999ms 超时全链路排查树，深入剖析系统时间 NTP 偏差、TUN 驱动冲突、DNS 污染回环与机场入口阻断的实操判定法。

TY

梯云社编辑部

Network Research · 2026

在使用 Clash Verge Rev、Mihomo Party 或 sing-box 客户端时，几乎所有人都遭遇过这种抓狂场景：

点击测速，原本绿油油的延迟测速列表瞬间全部变成 “Timeout” 或红色的 “9999ms”，浏览器彻底断网打不开任何网页。

搜索 CSDN 或中文互联网，90% 的答案充斥着“重启电脑”、“重装客户端”、“关闭防火墙”等毫无技术含量的套话。

核心事实：一家成熟机场的数十个节点分布在全球不同机房（香港、日本、美国、新加坡），几乎不可能在同一秒内全部宕机。当所有节点统一变红超时，问题 99% 出在本地环境的公共协商层，而非节点本身。

梯云社技术组根据网络工程排错规范，整理出这份直击病灶的七步全链路排查树。

---

快速自查决策树（先判定故障层级）

                     所有节点测速同时 9999ms / Timeout
                                    │
               ┌────────────────────┴────────────────────┐
        本地公共协商层故障                         上游中转入口故障
  (时间偏差 / TUN网卡 / DNS回环)                 (入口服务器断流 / 订阅解析失效)
               │                                         │
       步骤 1 至 步骤 4                           步骤 5 至 步骤 7

---

第一步：检查系统时间 NTP 同步（最隐蔽也是最常见的坑）

这是新手 80% 踩中却完全意识不到的致命雷区。

  • 底层原理：现代代理协议（如 VMess、VLESS、Trojan、Shadowsocks-2022、Hysteria 2）以及 TLS 加密证书协商，对客户端与服务端的时间差有极其严格的时间戳校验。一旦你的电脑本地时间与国际标准时间偏差超过 60 秒，服务端会在 TCP 握手阶段直接强行中断连接，导致所有节点全部握死超时。
  • 排查实操：

- Windows 用户：右下角时间 -> 右键“调整日期和时间” -> 点击“立即同步”，确保同步状态显示绿色对勾； - macOS 用户：系统设置 -> 通用 -> 日期与时间 -> 开启“自动设置日期与时间”； - 同步完成后，彻底退出代理客户端核心，重新开启测试。

---

第二步：排查 TUN 虚拟网卡驱动与杀毒软件冲突

如果你开启了 TUN 模式（虚拟网卡接管系统全部流量），以下三种情况会引发全盘死锁：

  1. 多代理网卡打架：电脑上同时安装了其他加速器、企业 VPN（如 EasyConnect、GlobalProtect、Cisco AnyConnect），两个 TUN 驱动争抢系统默认路由出口，导致虚拟网卡死循环；
  2. 杀毒软件拦截：国内某些杀毒软件会静默拦截虚拟网卡驱动（如 wintun.dll），导致数据包进得去出不来；
  3. 修复手段：

- 先在客户端内关闭 TUN 模式，切换为传统的“系统代理（System Proxy）”模式； - 若切换为系统代理后测速立刻恢复正常，说明 100% 为 TUN 驱动或路由表冲突，重新以管理员身份运行客户端并重装 Wintun 驱动即可。

---

第三步：DNS 污染与混合模式（Mixed Mode）环路死锁

当客户端的 DNS 解析被污染，或者本地代理端口配置发生了回环死锁时，测速请求根本发不出去：

  1. 检查内置 DNS 配置：打开 Clash 配置，查看 dns 字段是否启用了 fake-ip。如果误将国内直连 DNS 配成了国外已被污染的纯文本 DNS（如 8.8.8.8 未走加密），会导致域名解析全部卡死；
  2. 推荐配置原则：

``yaml dns: enable: true enhanced-mode: fake-ip nameserver: - 223.5.5.5 - 119.29.29.29 fallback: - https://1.1.1.1/dns-query - https://8.8.8.8/dns-query ``

  1. 清理系统 DNS 缓存：在 Windows 命令行执行 ipconfig /flushdns，Mac 执行 sudo dscacheutil -flushcache。

---

第四步：检查测速地址与节点协议版本兼容性

很多时候“9999ms”只是测速本身的探测网址被墙，并不代表节点无法翻墙：

  1. 查看设置中的“延迟测试 URL（Latency Test URL）”；
  2. 如果默认填的是 http://www.google.com/gen_204，当节点配置了特定分流规则时可能被丢弃；
  3. 解决方案：将测速 URL 更改为更稳定的轻量地址：

- http://cp.cloudflare.com/generate_204 - https://www.gstatic.com/generate_204

---

第五步：区分是“自己本地网络”还是“机场入口机房挂掉”

如果前四步全部排查无误，依然全线飘红，我们需要判定是本地宽带故障还是机场上游故障：

  1. 手机断开 Wi-Fi，开启 5G/4G 移动蜂窝热点让电脑连接；
  2. 再次点击测速：

- 如果换成手机热点后瞬间全绿：说明是你家里的电信/移动宽带光猫、路由器防火墙拦截了特定端口，或者光猫拨号出现了 MTU 截断； - 如果换成手机热点依然全红：说明是机场的上游国内中转入口遭遇了物理断纤或集群维护。

---

第六步：更新订阅节点与核对到期状态

不要笑，大量用户超时是因为套餐流量用超或已到期，或者机场更换了后端服务器节点但客户端未同步：

  1. 在客户端订阅管理列表中，点击“更新订阅（Update Subscription）”；
  2. 观察是否能拉取到最新的节点列表；
  3. 登录机场后台控制台，查看当前剩余流量、重置日期与公告列表。

---

第七步：极客工程师的底线思维——常备容灾“冷备份”

网络连接受国际出口路由波动、光缆检修与不可抗力影响极深。任何将全部生产力押宝在单一服务商、单一套餐上的做法，都是不成熟的技术选型。

工业级防失联准则：

  1. 主力专线主攻日常生产力：选择纯物理 IEPL 专线（如梯云社实测晚高峰丢包仅 0.05% 的 云界线官方站点），保障工作日代码拉取、SSH 长连接与大模型秒回；
  2. 常备按量计费作为容灾备胎：切勿购买两个按月计费的同质化套餐（双份月租极度浪费）。必须搭配一个“流量永久有效、不限使用时间”的按量计费服务（如梯云社实测过的 神行加速官方站点，¥8 购买几十 GB 流量常年躺在客户端），一旦主力遇到极端故障，秒级无缝切换，彻底告别断网恐慌。

---

实验室总结：遇到 9999ms，记住排错口诀：“先对时间再换网，关掉 TUN 测系统，换个热点定真凶，备用按量防失联”。按照工程逻辑逐层剥离，任何网络故障都能在 3 分钟内准确定位。
