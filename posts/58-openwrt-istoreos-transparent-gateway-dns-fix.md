# 【架构避坑】OpenWrt / iStoreOS 软路由透明代理全解：彻底根治 DNS 污染死循环与国内断网

在家庭网络升级或小型外贸工作室组网中，利用迷你主机（如 N100、J4125）刷入 **OpenWrt** 或 **iStoreOS** 搭建旁路由透明网关，是极客实现全屋无感翻墙的主流方案。

然而，几乎超过 80% 的新手在配置完成后，都会陷入各种诡异的网络灵异事件：

- **国内微信、网银、淘宝频繁转圈甚至打不开**，国外网站速度却正常；
- **主路由与旁路由互相争抢 DHCP 网关**，导致手机 Wi-Fi 频繁断连、获取不到 IP；
- **DNS 解析产生死锁回环**：OpenClash 或 PassWall 进程 CPU 占用飙升 100%，内网疯狂发包导致路由器死机。

## 一、 旁路由拓扑真相：流量到底是怎么走丢的？

理解旁路由（旁网关）的核心，在于理清**“去程与回程”**的非对称路由陷阱：

```
标准旁路由数据拓扑模型：
终端设备 (192.168.1.100) 
      │ (设置网关为旁路由 192.168.1.2)
      ▼
旁路由 (192.168.1.2: OpenWrt/iStoreOS) 
      │ (分流判断：国外流量通过代理内核加密出海，国内流量直连)
      ▼
主路由 (192.168.1.1: 光猫/硬路由) 
      ▼
运营商公网出口 (ISP)
```

**最致命的错误：非对称回程**  
终端设备将网关指向了旁路由，旁路由把国内数据包转给了主路由。主路由把数据发到国内互联网后，收到回包时，因为目标 IP 是终端设备（`192.168.1.100`），主路由通常会**直接在局域网二层交换机把包发回给终端**，完全绕过了旁路由！

终端收到了一个来自主路由的响应包，但终端当初发出的请求是给旁路由的（连接状态不匹配）。终端防火墙直接判定此包非法并丢弃，导致**国内网络直接断流瘫痪**。

## 二、 根治“国内断网”两大核心防火墙手术

要彻底解决上述非对称路由导致的国内网站打不开，必须在 OpenWrt 的防火墙中进行针对性修复：

### 1. 强制启用伪装（NAT MASQUERADE）
在 OpenWrt 后台 -> 网络 -> 防火墙 -> 自定义规则（或终端 `/etc/firewall.user`）中追加以下规则：
```bash
# 强制让所有经过旁路由 lan 接口的数据包进行源地址转换 (SNAT)
iptables -t nat -A PREROUTING -p udp --dport 53 -j REDIRECT --to-ports 53
iptables -t nat -A POSTROUTING -o br-lan -j MASQUERADE
```
> **原理说明**：开启此规则后，旁路由发给主路由的数据包会被重写为“来自旁路由自身”。主路由回包时必须先回给旁路由，再由旁路由返回给终端设备，连接会话状态完整闭环。

### 2. 避免国内网站走代理的规则配置
关于如何从客户端分流层面杜绝局域网与国内直连污染，请同步参考站内实战指南：[配置绕过大陆局域网规则实操](posts/20-local-sites-bypass-routing-guide/)。

## 三、 彻底根除 DNS 污染回环风暴（Fake-IP 最佳实践）

软路由 CPU 飙升与死循环，99% 是因为 DNS 转发形成了贪吃蛇回环。

### 推荐的高可用 DNS 拓扑：
1. **主路由仅充当物理交换机与 PPPoE 拨号**：不要开启主路由复杂的 DNS 过滤；
2. **终端设备的 DNS 强制指向旁路由 IP**（或在主路由 DHCP 中下发 DNS 为 `192.168.1.2`）；
3. **旁路由内核采用 Fake-IP 模式**：
   - 国内域名（通过 geoip/geosite cn 识别）交给主路由上游运营商 DNS（如 `223.5.5.5`、`119.29.29.29`）；
   - 国外域名由内核直接返回保留段伪 IP（`198.18.0.1/16`），避免本地向公共网络查询导致严重 DNS 污染。
